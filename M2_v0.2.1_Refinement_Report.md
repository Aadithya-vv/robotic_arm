## Improvements

- Added `AdaptiveVisionProcessor` behind the existing ENG-009 provider protocol. Optional OpenCV performs white balance, CLAHE, adaptive gamma, brightness/contrast correction, denoising, sharpening, adaptive thresholding, edges, morphology, contours, corners, texture analysis, shape filtering, and bounding refinement. A deterministic multi-region fallback works without OpenCV.
- Produces independent candidates rather than one full-frame box, with immutable geometry, appearance, component-score, motion-vector, confidence, frame, and timestamp context through existing Vision records.
- Configured Scene retention for 300 missed updates so stable IDs survive long gaps without changing ENG-010 contracts.
- Added exact-pixel frozen-frame crop selection, draggable/resizable selection, user metadata capture, Object Library browsing/search/sort/details/delete, and ENG-006 public Memory persistence.
- Added a five-minute rolling monitor covering Camera, pipeline, errors, performance, objects, detections, tracking, and reset activity.
- Expanded export with runtime/system data, Engine health, validation, Camera/Vision/Scene state, objects, descriptors, relationships, logs, exceptions, FPS, performance, Memory statistics, snapshot, timeline, and recent events.
- Added graceful provider switching, repeat-safe connect/disconnect, capture-before-connect handling, live-stop behavior, and in-process Perception Reset.
- Enlarged preview and overlays for candidate boxes, IDs, confidence, and centers.

## Limitations

- Classical computer vision cannot reliably assign real-world class names such as bottle or laptop. v0.2.1 produces visual candidates; users may label saved crops only in the application library.
- OpenCV behavior depends on local installation and input. YOLO, Grounding DINO, SAM, and similar models remain future provider options and are not implemented.
- The host Python installation requires working Tk/Tcl support for desktop window construction.
